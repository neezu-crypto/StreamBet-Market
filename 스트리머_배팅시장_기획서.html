StreamBet Market

스트리머 배팅시장 — 방송 중 실시간 이벤트에 배팅하는 가상 재화 게임 · 기획서
재화 가상 재화 (현금성 없음) 스택 Firebase RTDB + GitHub Pages 초기자산 1,000,000
01

개요

방송 중 실시간으로 발생하는 이벤트에 시청자들이 가상 재화로 배팅하는 게임. 방송 내용은 예측이 불가능하고 실시간으로 변하기 때문에, 정해진 배팅 항목뿐 아니라 유저가 직접 배팅 주제를 제안할 수 있는 구조를 핵심으로 한다.

기존 프로젝트와의 관계 — SOOP STOCK 등 기존 게임과 기술 스택을 공유하지만, 자산 시스템은 독립적으로 운영한다.
02

배팅 주제 카테고리

사전 정의 카테고리 (자동 · 반자동 판정)

구분예시판정 방식
게임 방송이번 판 승/패, 킬수 구간, 목표 달성 여부스트리머 확정 · 다수결
토크 · 저챗키워드 발언 여부, 후원 금액 구간스트리머 확정
시청자 지표N분 후 시청자 수 증감, 채팅량 목표API 연동 자동 판정
합방 · 대결스트리머 간 승부, 미니게임 결과스트리머 확정 · 다수결

초기 버전은 자동 판정이 가능한 카테고리부터 우선 구현하여 판정 시비 리스크를 최소화한다.

유저 제안형 배팅 (템플릿 방식)

자유 텍스트가 아닌 템플릿에 값을 채우는 방식으로 제안하여 판정 가능성을 담보한다.

예: [스트리머]가 [N분] 안에 [행동]을 할 것이다

제안 시 함께 지정: 판정 방법배팅 가능 시간배팅 마감 시점이벤트 시작·마감 시점

본인 제안 배팅 참여 허용 — 시크릿 창 등 우회 접속이 어차피 가능한 웹게임 특성상, 원천 차단보다는 배팅 한도 등 완화 장치로 대응한다.
03

대전 유형

배팅 주제 개설 시 아래 3가지 유형 중 하나를 선택한다. 개인전 · 1vs1은 이진 판정, 단체전은 다중 판정으로 정산 로직이 달라진다.

유형대상결과 형태배당 계산
개인전스트리머 1인의 승부 (예: N시간 안에 X 가능/불가능)성공 · 실패 (이진)찬성/반대 두 풀로 단순 분배
1vs1 대전스트리머 vs 스트리머승 · 패 (이진)두 풀로 단순 분배
단체전여러 스트리머 추가 후 1위 예측순위 (다중)N개 풀로 분산, 배당 편차 큼

단체전 설계 시 고려사항

  • 배당 편차 — 인기 스트리머에 배팅이 몰리면 배당이 낮아지고 비인기 스트리머는 배당이 치솟는 패리뮤추얼 구조. 몰빵 방지를 위해 최소 배당 하한선 검토
  • 참가자 변경 — 방송 중단 등으로 중도 이탈/추가 가능성 → 배팅 마감 시점 이후 참가자 목록 고정
  • 순위 판정 기준 명시 — 시청자 수 1위 / 게임 순위 1위 / 스트리머 자체 선언 등, 검증 단계에서 판정 기준을 템플릿에 필수 입력

템플릿 필드 (대전 유형 공통)

대전 유형 : [개인전 / 1vs1 / 단체전] 참가자 : [스트리머 1명 / 2명 / N명 (단체전만 추가 가능)] 판정 기준 : [자유 텍스트 또는 사전 정의 항목 선택] 판정 방법 : [관리자·인증 스트리머 검증 / 좋아요 다수결] 시간 구조 : [배팅 가능 시간 / 배팅 마감 / 이벤트 시작·마감]
04

배팅 주제 검증 프로세스

유저 제안 배팅은 오픈 전 검증 단계를 거친다. 검증 방식은 2가지 중 선택:

  1. 관리자 / 인증 스트리머 직접 검증
  2. 다수 익명 계정의 '좋아요' 수 통과 (라이트 검증, 실시간성 확보)
주제 제안 (템플릿 입력) │ ▼ 검증 (관리자 · 인증 스트리머 승인 OR 좋아요 다수결 통과) │ ▼ 배팅 오픈 → 배팅 마감 → 이벤트 진행 → 정산
05

스트리머 인증 시스템

스트리머 본인이 직접 신청하는 구조:

  1. 스트리머가 닉네임 + SOOP 아이디 입력하여 신청
  2. 관리자가 검수 후 승인 · 반려
  3. 승인된 스트리머는 다음 권한을 얻는다:
    • 자신의 방송과 관련된 배팅 주제 검증 권한
    • 메인페이지 홍보 배너에 본인 방송국 노출
06

시간 구조

배팅 게임의 시간 흐름을 3가지로 명확히 분리하여 관리한다.

구분설명
배팅 가능 시간유저가 배팅을 넣을 수 있는 구간
배팅 마감 시점배팅 가능 시간의 종료 (이벤트 시작 전 마감 가능)
이벤트 시작 · 마감 시점실제 결과가 갈리는 구간, 정산 트리거

세 시점을 분리함으로써 "이벤트는 진행 중이지만 배팅은 마감된" 상태를 자연스럽게 구현한다.

07

자산(재화) 시스템

  • 초기 자산 — 1,000,000원 (SOOP STOCK 등 기존 게임과 동일한 기준)
  • 자산 분리 원칙 — 배팅시장 재화는 타 게임과 실시간 완전 공유하지 않음
    • 계정(로그인/UID)만 공유하여 원 클릭 접근성 확보
    • 게임 간 이동은 제한적 환전 기능으로만 연결 (비율 · 일일 한도는 추후 확정)
왜 완전 공유가 아닌가 — 한쪽 게임의 밸런스 붕괴나 버그가 실시간 자산 공유 시 다른 게임 경제로 전염되는 것을 방지하기 위함.
08

어뷰징 방지 장치

카지노 모델 참고

  • 최대 배팅 금액 제한 — 1회 배팅당 상한선 (보유자산 비례 또는 고정액)
  • 최소 참여자 수 조건 — 참여 인원 미달 시 정산 무효 · 환불 처리 (자작극 방지)
  • 연속 배팅 취소/재배팅 쿨다운
  • 일일 배팅 총액 한도
  • 신규 계정 배팅 한도 단계적 상향
  • (검토 중) 본인이 제안한 배팅 참여 시 최대 배팅 한도를 낮게 적용
09

정산 방식

유형정산 방법
자동 판정형 (시청자 수 등)백엔드 자동 정산
유저 제안형채팅 다수결 투표 기본, 인증 스트리머 있으면 스트리머 확정 최우선
